# Сервер Amix: пробный период, лицензионные ключи, промокоды

Регистрации нет. Устройство опознаётся по идентификатору (на сервере хранится только хэш). Сервер считает
**7 дней бесплатно с первого запуска**, проверяет и активирует **лицензионные ключи** и **промокоды**.
Все проверки только на сервере; клиент получает результат. Секретов и кодов в приложении нет.

## Что здесь
| Файл | Назначение |
|---|---|
| `functions/access.js` | пробный период 7 дней по устройству, статус PRO |
| `functions/codes.js` | генерация и активация ключей и промокодов (один раз, срок, тип, защита от подбора) |
| `functions/handlers.js`, `index.js` | три функции: `access`, `activateKey`, `promo`; ограничение частоты запросов |
| `functions/admin.js`, `scripts/admin.js` | создание, список, статистика, отзыв, выгрузка в CSV |
| `firestore.rules` | клиентам закрыт весь доступ к базе, пишет только сервер |
| `archive-yookassa/` | прежний код автооплаты, не используется |

## Проверка без Firebase (26 тестов)
    cd functions
    node --test "test/*.test.js"

## Настройка сервера (делаете вы, один раз)
1. В Firebase включите **Firestore** (режим «Production») и тариф **Blaze** (функции на бесплатном тарифе не работают).
2. Установите Node.js 20, затем `npm i -g firebase-tools` и `firebase login`.
3. В папке `server`: `firebase use --add` (выберите проект), затем `cd functions` и `npm install`.
4. Необязательно, но желательно: файл `functions/.env` с одной строкой `RATE_SALT=любая_длинная_случайная_строка` (соль для хэшей адресов).
5. Разверните: `firebase deploy --only functions:access,functions:activateKey,functions:promo,firestore:rules`
6. Ключ для административного скрипта: в консоли Google Cloud, **IAM → Сервисные аккаунты**, создайте ключ JSON. В PowerShell:
       $env:GOOGLE_APPLICATION_CREDENTIALS="C:\путь\service-account.json"
   Ключ нигде не публикуйте.

## Создание кодов (на вашем компьютере, коды видите только вы)
    cd functions
    node scripts/admin.js generate promo --count 1000 --days 30            # 1000 промокодов на 30 дней PRO
    node scripts/admin.js generate promo --count 1000 --days 30 --valid-days 90   # и со сроком действия кода 90 дней
    node scripts/admin.js generate keys --count 50 --type m1               # 50 ключей на месяц (m1=30, m6=180, m12=365, forever)
    node scripts/admin.js generate keys --count 10 --days 14 --type custom # свой срок в днях
Скрипт создаёт коды в базе и сохраняет **CSV-файл** с ними (откроется в Excel). Ключи из CSV вы продаёте и отправляете покупателям.

    node scripts/admin.js list keys --status used       # какие ключи уже использованы
    node scripts/admin.js export promo --out promo.csv  # выгрузка всех промокодов со статусами
    node scripts/admin.js stats promo                   # сколько всего, использовано, отозвано, просрочено
    node scripts/admin.js revoke keys AMIX-XXXX-XXXX-XXXX-XXXX   # отключить ключ

Формат: ключ `AMIX-XXXX-XXXX-XXXX-XXXX` (80 бит случайности), промокод `PROMO-XXXX-XXXX-XXXX` (60 бит). Каждый код активируется один раз.

## Защита
- 10 неудачных попыток активации за час блокируют устройство на час; 300 запросов в час с одного адреса; 30 новых устройств в час с одного адреса.
- Идентификаторы устройств и адреса хранятся только хэшами.
- Пробный период нельзя сбросить удалением данных приложения: идентификатор берётся из системы (ANDROID_ID) и не меняется при переустановке.
  Ограничение: сброс телефона до заводских настроек или модификация приложения (root) его обходят.

## Правила Firestore и веб-версия
`firestore.rules` закрывает от клиентов всё, что относится к ключам, промокодам и устройствам приложения (`licenses`, `promos`, `nativeDevices`,
`rateLimits`), потому что их читает и пишет только сервер. Для веб-версии Amix с входом через Google правила ограничивают запись полей Pro
из браузера. Если веб-версия у вас работает в том же проекте, публикуйте правила, когда готовы это принять
(`firebase deploy --only firestore:rules`); для приложения они не нужны, оно в базу напрямую не ходит.
